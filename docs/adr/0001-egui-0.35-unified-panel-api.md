# ADR 0001: Target egui/eframe 0.35's unified Panel API

- **Status:** Accepted
- **Date:** 2026-07-27
- **Phase:** 1 (Core Shell)

## Context

The PRD (§3.2, §7) specifies the GUI stack as `eframe` / `egui` and, in the
Phase 1 roadmap, names the layout containers as `SidePanel::left`,
`SidePanel::right`, and `CentralPanel` — the API as it existed in older egui
releases (≤ 0.31).

When we added the dependency, Cargo resolved the latest stable release,
**eframe/egui 0.35.0**, which changed the relevant API:

- `SidePanel` and `TopBottomPanel` no longer exist as separate types. They are
  unified into a single `egui::Panel` with constructors `Panel::left`,
  `Panel::right`, `Panel::top`, and `Panel::bottom`.
- Panel sizing moved from axis-specific builders (`default_width` /
  `default_height`) to a single axis-relative `default_size` (plus `min_size`,
  `max_size`, `exact_size`, `size_range`).
- Every panel's `show` now takes a `&mut Ui` rather than a `&Context`, so
  panels nest naturally by passing the parent `Ui` down. `show_inside` is
  deprecated (renamed to `show`).
- The `eframe::App` trait entry point changed from
  `update(&mut self, ctx: &Context, frame)` to
  `ui(&mut self, ui: &mut Ui, frame)`. The `Context` is reached via `ui.ctx()`.

## Decision

Target the **eframe/egui 0.35 API** as-shipped, rather than pinning an older
version to match the PRD's literal type names.

Concretely:

- Build the three-panel layout with `Panel::left` (projects pane),
  `Panel::right` (context column), and `CentralPanel` (editor canvas).
- Nest the context column's Quick Info sub-panel as a `Panel::bottom` shown
  inside the right panel's `Ui`.
- Implement `eframe::App::ui`; obtain the `Context` for keyboard-shortcut
  handling by cloning `ui.ctx()` (a cheap `Arc` handle) so the immutable borrow
  of `ui` ends before we draw into it.

## Consequences

- The code diverges from the PRD's literal API names; the PRD's `SidePanel::…`
  phrasing is now historical. This ADR is the record of that divergence.
- We stay on the maintained release line and get current fixes/features rather
  than carrying an outdated pinned version.
- Future egui upgrades may bring further API churn; because all layout *logic*
  lives in the egui-free `Workspace` struct (unit-tested), only the thin
  `MarkSpaceApp` glue is exposed to such churn.
